6. PIEGES CONNUS (tests et outillage)
-------------------------------------
  - Pest : toHaveKey($cle, $valeur) : le 2e argument est la VALEUR ATTENDUE, pas un message. Les messages sont
    acceptes par toBeTrue(), toBeArray(), etc.
  - Fonctions et constantes d'un fichier de test sont GLOBALES : les prefixer (ft*, fc*, fd*, fs*, pm*, ms*, ap*,
    tp*, FD_, FS_, TP_...). Les jeux de donnees Pest sont evalues AVANT le demarrage de l'application : pas de
    config() ni de view() dans une fonction appelee par un dataset.
  - Un test qui utilise config(), view() ou la base va dans tests/Feature. Pour fixer une date :
    Carbon::setTestNow(Carbon::parse($d, config('app.timezone'))) et le remettre a null en afterEach.
  - MUTATION DE CONTROLE : ne JAMAIS restaurer un fichier avec "git checkout -- <fichier>" tant qu'il n'est pas
    commite (cela ecrase les modifications non commitees, c'est arrive sur deploy-hardening). Restaurer depuis
    une copie en memoire, ou commiter d'abord.
  - Ne taguer qu'apres "master -> master" (master == origin/master) ; jamais un commit rouge.
  - Un zip livre SANS dossier racine (sinon Expand-Archive cree un sous-dossier). Un script PowerShell qui s'arrete
    apres l'extraction du zip l'a deja SUPPRIME : ne pas le relancer tel quel ; verifier d'abord avec git log,
    git tag et git status.
  - Un echec de push peut etre reseau ("Could not resolve host") : le hook de pre-push a alors deja valide Pest
    complet ; relancer le push suffit.
  - Dettes inchangees : CSP avec unsafe-inline/unsafe-eval, anonymisation de visitor_hash avant 13 mois, SMTP
    (Gmail, mot de passe d'application) jamais eprouve, scripts de deploiement jamais executes, rendu
    Sombre/Clair non revu ecran par ecran.
